# Playbook: product/feature-spec

problem → research → spec → review.

## Steps

1. **Planner** — define the problem statement, target user, and done-criteria (problem validated by research, spec covers user stories, edge cases, success metrics).
2. **Researcher** — validate the problem: existing solutions, user evidence, technical constraints; tag confidence.
3. **Builder** — write the feature spec: problem, user stories, scope/non-goals, edge cases, success metrics, open questions.
4. **Reviewer** — check done-criteria first; blocker for unvalidated problem assumptions or missing success metrics; verdict.
5. **Router** — route per verdict; capture one learning line.
